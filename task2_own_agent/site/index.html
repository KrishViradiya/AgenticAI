The Future of Software Engineering

Our experience with coding agents so far points to a future where machines can move quickly, but good engineering still depends on people who know what “right” means.

  • Agents are useful teammates. Let them tackle boilerplate, tests, scripts, configurations, debugging clues, and first drafts.
  • Context is the human advantage. Agents can miss why a system exists, what users need, and which trade-offs matter.
  • Clear specifications save time. Breaking a problem into explicit tasks helps both people and agents do better work.
  • Review and verification are core engineering. Check correctness, usability, security, and operations before trusting the output.

One friendly disagreement: how much should agents run on their own?

More autonomy: Keval can imagine agents deploying, monitoring, and fixing systems when engineers give them clear permissions, tests, and rollback plans.

More caution: Nirav emphasizes defining correctness and reviewing every line, while Harsh stresses that agents still lack the context behind a system’s design.

Either way, handing an agent a vague task and production access is not a strategy. It is a very fast way to learn what your rollback plan is for.

Our shared prediction: software engineering shifts from writing every line to specifying, directing, reviewing, and verifying the work—and the clearest thinker in the room remains a valuable teammate.
